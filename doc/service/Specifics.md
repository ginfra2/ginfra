# Specifics

This is the additional information available to Ginfra on how to run the service.

## Configuration 

Specifics are contained in the file specifics.json.  The file must
be present at runtime but may be an empty json (simple a "{}".)

## Full Example

```
{
   "meta": {
      "version": 1,
      "name": "giuser",
      "type": "apiecho",
      "module_name": "gitlab.com/ginfra/gservices/service_giuser",
      "serviceclass": "giuser",
      "invocationcmd": ""
   },
   "exposed": {
      "4317":{
         "name": "Otel Collector receiver grpc",
         "serviceclass":  {
            "name": "collector",
            "url": "grpc://<<<host>>>:<<<port>>>/"
         }
      },
      "4318":{
         "name": "Otel Collector receiver http"
      }
   },
   "expect": {
      "web_port": {
         "description": "The port that will host the web server."
      }
   }
}
```

## Sections

### Meta

#### Example

```
"meta": {
      "version": 1,
      "name": "giuser",
      "type": "apiecho",
      "module_name": "gitlab.com/ginfra/gservices/service_giuser",
      "serviceclass": "giuser",
      "invocationcmd": ""
   }
```

#### Description

This is the only required part of the specifics.

Name, type and serviceclass are required.  Only version 1 is supported.  Name and serviceclass can be and usually
are the same.  Module_name is only used by the generator, so if the service isn't generated by Ginfra, you can ignore it.

Invocationcmd tells ginfra to use a command other than the default to start the service locally (like on your laptop and
not in a container).  If not set, it will try to run a script named start_local.sh or start_local.cmd, depending on
if your system is unix/linux/etc or windows.  So create the script if you want ginfra to be able to start your service
this way.

### Exposed

#### Example

```
   "exposed": {
      "4317":{
         "name": "Otel Collector receiver grpc",
         "serviceclass":  {
            "name": "collector",
            "url": "grpc://<<<host>>>:<<<port>>>/"
         }
      },
      "4318":{
         "name": "Otel Collector receiver http"
      }
   }
```

#### Description

Exposed tells Ginfra what ports it wished to be exposed.  Each entry represents a port.
The key will be the port value as a string.  Within the entry, the following are supported:

```
    "name": "Otel Collector receiver grpc",
```

This does not actually do anything.

```
    "serviceclass":  {
        "name": "collector",
        "url": "grpc://<<<host>>>:<<<port>>>/"
    }
```

Serviceclass is a discoverable service entry point.  Each exported port can have one serviceclass.  
The declared "name" (here "collector") will be combined with the service's default serviceclass to
make the fully qualifies serviceclass name.  For instance, if this example's service was called
'giuser' than this port's serviceclass would be 'giuser/collector'.  (Note: a service can override
its default serviceclass name, but there is no specific use case for doing that.)

The "url" can be in any form, but '<<<host>>>' and '<<<port>>>' will be replaced with their respective values.

### Expect

#### Example

```
{
   "expect": {
      "web_port": {
         "description": "The port that will host the web server.",
      }
   }
}
```

#### Description

This describes the service specifics the service expects to be set.  This should be kept to the absolute minimum.

In the example, web_port represents the name of the specific.  A description would be give, but is not required.
